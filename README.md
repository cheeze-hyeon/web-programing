# 이게 어디가 웃긴데?

**ComedyGym**은 AI가 셀프 비평 후 수정한 농담이 실제 인간에게 더 웃긴지, 같은 소재의 원고를 블라인드로 비교하는 실험형 웹 작품입니다.

## Question

AI가 스스로 비평하고 수정한 농담은 실제 인간에게도 더 웃길까?

## Background & Motivation

저는 컴퓨터공학을 공부하고 개그동아리에서 코미디를 기획하고 공연을 준비합니다. AI가 반전과 아이러니를 갖춘 농담을 만들고 그 구조를 설명해도, 실제로 읽으면 재미없을 수 있다는 경험에서 질문이 시작됐습니다. AI에게 “니가 이것들을 대체 뭐가 웃기다고 짠 건지?”라고 물으며, 스스로 농담을 비평하고 고치는 것과 사람을 실제로 웃기는 것이 같은지 궁금해졌습니다. 이번 원고는 종교인 개인을 비웃기보다 신앙의 논리와 제도 사이의 모순을 소재로 삼습니다. 종교 풍자는 관객의 신앙과 경험, 공연 장소에 따라 웃음과 불편함이 달라질 수 있어 청중 맥락도 중요합니다.

## Experiment

같은 소재의 기존 농담과 AI가 셀프 비평한 뒤 수정한 농담을 한 쌍으로 준비했습니다. 소재 순서는 고정하고 각 쌍 안에서 A/B 배치를 무작위로 정합니다. 관객은 A, B, 또는 둘 다 재미없음을 고르고, 선택 후에야 어느 쪽이 기존 원고/수정본인지와 AI의 비평·수정 전략을 확인합니다. 이유와 메모는 선택 사항입니다.

실험에는 종교 풍자 8개 소재의 원고 쌍을 사용합니다. 사용자가 제공한 AI 비평과 수정 전략을 결과 공개 화면에서 함께 보여줍니다. 원고의 길이와 바뀐 장치, 풍자 대상은 쌍마다 다르므로, 이 작은 비교만으로 셀프 수정의 보편적 효과를 단정할 수는 없습니다. 이 자료에는 실제 관객 반응이 없으며, 앱에 기록되는 것은 향후 이용자의 개인 브라우저 평가입니다.

## AI USE NOTE

- **AI 활용:** 농담 초안 작성, 초안의 논리와 펀치라인을 돌아보는 셀프 비평, 수정 아이디어 제안에 활용했습니다. 이번 웹 MVP 구현과 문서 정리에도 AI를 사용했습니다.
- **인간의 역할:** 프로젝트 질문, 풍자 방향과 최종 원고 선택을 인간이 판단합니다. 제시된 AI 자기 비평과 수정 설명은 실제 웃김을 입증하는 자료가 아닙니다. 관객의 실제 반응은 아직 확인되지 않았습니다.
- **선택하지 않은 확장:** 실시간 LLM 생성, 다중 에이전트, 서버 기반 투표 집계는 이번 MVP에 포함하지 않았습니다.
- **한계:** 논리적 모순을 짚거나 농담의 장치를 붙이는 AI의 분석이 실제 웃음의 증거는 아닙니다. 종교 풍자의 수용은 청중의 경험과 장소에 민감할 수 있습니다.
- **웹 개발 협업:** 정적 HTML/CSS/JavaScript, 무작위 블라인드 비교, 개인 로컬 기록과 JSON 내보내기, 발표 자료를 구현했습니다. 브라우저별 실제 사용성 관찰은 [실제 작업 후 작성]으로 남겨 둡니다.

## Failures & Learnings

**현재까지의 판단:** 논리적으로 정리된 모순이 모두 웃음으로 이어지는 것은 아닙니다. 어떤 후보는 풍자적 관찰이나 사회 비평에 더 가까울 수 있습니다. 이는 원고에 대한 창작자의 분석이며, 실제 관객 평가 결과는 아닙니다.

**아직 검증하지 않은 가설:** 흥미로운 발상을 찾는 단계와 문장/펀치라인을 다듬는 단계는 다른 창작 판단일 수 있습니다. 종교 풍자는 관객 맥락에 따라 웃음과 불쾌감이 달라질 수 있습니다. 실제 관객 반응을 수집하기 전에는 두 가설 모두 결론 낼 수 없습니다.

## Future Work

- Comedy Writer / Critic / Rewriter 역할 비교
- 동의와 안내를 갖춘 실제 인간 반응 수집
- Human Preference Ranking Model 탐색
- Hugging Face 모델 또는 데이터셋 공개 가능성 검토
- 종교 및 코미디 창작물의 저작권과 윤리적 사용 기준 수립

## 실행 및 배포

`index.html`을 열면 사이트가 작동합니다. 

```sh
python3 -m http.server 8000
```

`http://localhost:8000`에 접속합니다. GitHub Pages에서는 저장소 **Settings → Pages**에서 배포 브랜치와 루트(`/`)를 선택합니다. 빌드 단계나 API가 없고 상대 경로를 사용합니다. 웹폰트는 Google Fonts에서 불러오며 오프라인에서는 시스템 글꼴이 적용됩니다.

## 조작 및 데이터

- 평가 시작 후 8개 소재를 한 번씩 비교합니다. 각 쌍의 A/B 위치만 무작위로 바뀝니다.
- 매 라운드 A/B 중 하나 또는 ‘둘 다 재미없다’를 선택할 수 있습니다.
- 응답 후 기존 원고/수정본의 정체, AI 셀프 비평과 수정 전략을 확인합니다.
- 선택과 선택적 이유/메모는 개인 브라우저에 저장하고, JSON으로 내보낼 수 있습니다.
- 미구현: 서버 저장/공유, 전체 관객 통계, 실제 사용자 연구, 실시간 LLM 생성.
